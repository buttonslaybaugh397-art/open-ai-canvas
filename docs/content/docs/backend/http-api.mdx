# HTTP API 合同

路径前缀是 `/api`。前后端一起发布，不按 `/api/v1`、`/api/v2` 做路径版本。不兼容变更随版本一起改接口和调用方。

机器可读规范：运行中的 `GET /api/openapi.yaml`，源文件 `backend/internal/handler/openapi.yaml`。前端 TypeScript 仍走 `web/src/services/api` 的 `http`，不从 OpenAPI 生成客户端。

## 欢迎页开放配置

`GET /public/welcome` 无需登录，信封 `data` 仅包含布尔值 `welcomeEnabled`，响应禁用缓存。读取失败按标准错误信封返回。

管理员通过 `GET/PATCH /admin/settings/features` 读取和保存 `welcomeEnabled`，默认 `true`，与其他功能开关一起存入 `system_settings` 的 `feature_availability` JSON，并记录管理员审计。关闭后新访问 `/welcome` 的浏览器跳转到 `/`。

## 云端 Agent

所有 `/agent` 路径都需要登录 Cookie。`GET /agent/capabilities` 返回当前版本（2）、权限模式、上下文范围、技能和工具清单；`maxHistoryPairs: 0`、`maxSteps: 0` 表示不设固定对话 / 模型调用轮数，历史仍受 `maxHistoryBytes: 64000` 约束。Agent 运行由服务端任务 Worker 驱动，浏览器断开不会停止运行。

- `POST /agent/runs` 创建一轮；`POST /agent/runs/:id/messages` 以上一轮为父节点创建新的不可变轮次，两者返回 `{ run }`，追加后必须使用新的 `run.id` 订阅。
- 请求字段：`canvasId`、`prompt`、受管 `logicalModelId` 或 `channelId` + `channelModelKey`、`permissionMode: "read_only" | "request_approval" | "auto"`、`reasoningMode: "off" | "auto" | "deep"`、`profileRevision`、`skillIds`、`contextScope: [] | ["canvas"]`、`budget: { maxCredits, maxGenerationTasks, maxVideoSeconds }`、`idempotencyKey`。不接受密钥、自定义 URL、客户端历史或未知字段。
- 同用户同幂等键及相同请求返回同一运行；不同请求复用键返回 409。失败后重试同一提交应保留键。上一轮未完成时禁止追加；已完成、失败、取消或已拒绝的终态轮次作为不可变历史读取，即使其冻结的策略或节点能力版本早于当前服务，也可用于创建采用当前执行合同的新一轮，父运行不会被改写。旧版合同下仍活动或待审批的运行不得恢复执行。历史不设固定消息对数，JSON 最大 64000 字节，超限提示新建对话；历史结构损坏返回明确 409，不投影为通用 500。
- `POST /agent/runs/:id/approvals/:approvalId/decision` 的 `{ decision, reason? }` 可在批准图片生成时附带 `mediaSettings: { logicalModelId? | channelId? + channelModelKey?, size, quality }`。仅替换本次模型选择、画幅和质量，不允许修改目标、提示词、引用、模式或快照。服务端先无收费预检，失败保留待审批状态；成功原子更新审批调用、哈希及预览，提交任务时再次校验内容、资源归属、模型能力、价格与累计预算。相同参数重复批准幂等，不同参数复用已决定审批返回 409。
- 审批拒绝是独立终态 `rejected`，表示本次操作未执行；不会生成 `tool_failed`、继续调用模型、写入画布、提交生成任务或扣费。拒绝后的草稿按既有草稿策略保留，用户可在下一轮说明修改方向。
- 创建和追加消息可选择 `reasoningMode`，默认 `off`；`auto`/`deep` 为服务端行为策略与模型推理配置的选择，不等于允许暴露内部思维链。供应商能力由后端校验；声明式 Agent 渠道不支持时明确报错。推理可能增加耗时和费用。
- Cloud Agent 与首页创造的规划请求使用自动工具选择。OpenAI Chat Completion 兼容协议会把显式 `auto` 归一化为省略 `tool_choice`，沿用协议默认的自动选择语义；显式开启思考模式时还会在首个上游请求前移除 `required` 或指定函数对象。非思考模式仍保留艺术点评、提示词优化等结构化任务的强制函数选择。若上游隐式开启思考而本地未声明，仍按 `required` → `auto` → 省略字段做兼容重试。
- `GET /agent/profile?scope=user|project|canvas&projectId=...&canvasId=...` 按作用域读取生效的用户 → 项目 → 画布偏好；`PATCH /agent/profile` 用 `{ scope, projectId?, canvasId?, content, revision }` 更新单层（首次 revision 为 0，冲突返回 409）。读取返回各层独立数字 revision，以及合并文档的 `revision`/`hash`；新轮次携带合并 `profileRevision`，发生变化拒绝创建，已运行轮次仍用提交时固定的快照。system prompt 只包含层级、revision、hash 和长度清单，正文保存在运行快照中并由 `agent_profile_read` 按 user → project → canvas 顺序读取，不整本注入系统策略。偏好仅是非授权数据，不能扩展工具、节点或预算，不能绕过审批；最多 12000 字符/层。
- 系统行为策略与媒体默认策略是版本化、编译进后端发布物的资源，修改它们仍需发布后端，不是后台热更新；工具、校验、扣费和审批在代码侧强制执行。画布节点能力由服务端 registry 定义，工具 schema、创建、连线与画布摘要读取共同消费；新生成模式还必须接入媒体任务适配器，不能仅凭 md 或注册节点启用收费操作。
- 已安装且属于当前用户的技能在创建时只保存版本、哈希和文本文件路径，不预存全部正文，也不按所有选中技能正文合计 128KB 拒绝创建。`skill_read_file` 按需读取 `SKILL.md` 或必要引用，支持字符偏移 `offset`（默认 0），每页最多 12000 字符，返回 `hasMore` / `nextOffset`。读取时重新验证用户权限、启用状态和版本；技能更新后拒绝混读，需新开一轮。技能是不可信数据，不能创造工具、改变权限或覆盖系统规则。
- 模型上下文达到 96KB 或超过 24 条消息时，尝试移除较早工具结果中可重新读取的正文，保留工具调用/结果配对、用户原始要求、生成回执及最近完整工具轮次，并允许重新读取。此机制是确定性正文卸载，不是 LLM 语义摘要；不可压缩内容仍受 192KB 请求和 512KB 运行状态保护。技能读取事件只保存回执，不复制正文，正文页只进入模型对话。
- 平台支持工具全集为 `agent_profile_read`、`canvas_list_node_types`、`canvas_get_state`、`skill_read_file`、`task_get`、`model_list`、`canvas_apply_ops`、`generate_media`；单轮实际工具仍按偏好快照、技能、权限、画布上下文和生成预算裁剪。画布写入工具要求本轮授权 `contextScope: ["canvas"]`。禁止 shell、任意网络请求和外部 MCP。
- `canvas_list_node_types` 从服务端节点能力 registry 返回当前可用类型；可更新节点的 `updateFields` 同时包含字段类型、最大字符数和字段语义。模型不能从前端渲染器、技能或偏好文档推断额外能力。
- `canvas_apply_ops` 必须带 `snapshotHash`，每批最多 20 项；支持新增文本、Markdown、图片、视频、音频、分组与分镜表节点，以及 `connect_nodes` 引用连线。媒体占位节点的 `content` 是提示词，不是媒体 URL；只建节点不提交收费生成。`update_node` 的字段映射完全由能力 registry 决定：文本 / Markdown 可改标题和正文，图片 / 视频 / 音频可改标题和下一次生成使用的提示词草稿；媒体更新参数中的 `content` 写入 `metadata.composerContent`，不会覆盖媒体结果 `metadata.content`、已提交提示词 `metadata.prompt`、任务状态或引用状态。锁定节点、删除、任意元数据写入、自连接、重复边与不存在的端点仍被服务端拒绝。
- `model_list` 复用生成面板的当前模型目录。生成前传 `mode` 和实际 `referenceNodeIds`（无参考传空数组），服务端读取当前用户画布内的就绪资源，按真实素材类型、数量及生成操作构建意图并调用统一能力匹配，不让多图生视频落入仅文生视频候选；返回 `intent` 供核对。空参数仍可浏览完整目录；空候选不降级到不匹配模型。每项的 `selection` 是 `logicalModelId` 或 `channelId` + `channelModelKey`，工具调用必须原样选择一种，不猜 ID 或混用；时长、画幅、音频、价格仍需核对返回配置，任务准入再次强校验。
- `generate_media` 支持图片 / 视频 / 音频：必填 `mode`、`prompt`、`snapshotHash`、`nodeId`（可续用草稿，无草稿时才新建）、`title`、有序 `referenceNodeIds`（无参考传空数组），再加一种模型选择；图片 / 视频要求 `size`，视频要求正数 `durationSeconds`，图片 / 音频时长为 0。可传来源节点 `sourceNodeId`、`quality`、视频 `videoGenerateAudio`。`sourceNodeId` 仅接文本 / 镜头提示词节点；参考图片、视频、音频只放 `referenceNodeIds`，无文本来源时留空且不重复传入。引用从当前画布节点的账号资源解析，校验归属、类型、就绪状态和模型能力，不接受任意 URL。图片生成仅接图片参考；视频可按模型能力接图片、视频、音频参考；音频生成当前仅支持文本输入。
- 参数选择与收费授权分开：用户明确说“随便 / 你决定 / 按默认”时，Agent 可从当前目录选择能力及预算匹配的模型，优先用户最近明确使用的可用模型，其次价格清楚的低成本选项；支持时沿用参考图原始比例，否则选目录默认，时长用目录默认。未要求音频且模型不支持时用默片。用户接受已推荐方案后不再要求特定确认口令；仅真正缺失或冲突的阻塞项一次性询问。本轮已有目录结果应复用。以上是 Agent 的参数选择策略，服务端仍强校验具体规格，不提供绕过预算 / 能力校验的默认兜底，也不绕过独立收费审批。
- 媒体参数先进行无任务、无预留账单的准入校验，再在同一事务创建草稿节点、来源 / 资产连线及待审批检查点；`approval_requested` 和运行中的 `approval` 携带目录真实 `modelName`。用户批准后才在事务中绑定任务、创建预留账单并更新检查点；拒绝或取消保留未生成草稿，不提交媒体任务。`nodeId` 可续用同类型、未锁定、idle、无任务且无媒体结果的空白占位节点或当前运行草稿；跨轮 Agent 草稿还要求原运行属于同一用户和画布、已结束且清理完成。续用必须重新读取快照并重新审批，不能复用旧审批、覆盖已有任务或成品，不能通过循环新建节点绕过限制。画布读取的 `generationDraft` 提示未提交、原运行状态、是否仍在清理及仍需审批；写入仍重新强校验。已明确审批的规格不得被模型默认值静默替换。媒体终态回写原节点；已删除或已换任务的节点不自动复活，结果仍可从任务中心查看。
- Agent 的 `snapshotHash` 忽略顶层 `viewport`、`updatedAt`。`canvas_get_state` 另返回 `mediaSnapshotHash`，供 `generate_media.snapshotHash` 使用，并额外忽略节点 `position`；创建生成草稿后的审批也固定该内容哈希。因此移动图片或草稿不会使生成审批失效，执行时保留最新坐标；节点内容、素材、锁定状态和连线变化仍需重新读取并审批。画布修改与撤销继续使用包含位置的 `snapshotHash`，数据库写入仍使用完整快照 CAS。客户端刷新保留本地视口。
- `read_only` 只允许读取；`request_approval` 对写画布和媒体生成暂停为 `waiting_approval`；`auto` 可在预算内执行已授权画布操作，但图片 / 视频生成始终独立审批，不能绕过。`maxGenerationTasks` / `maxVideoSeconds` 为非负整数，0 表示该项不设业务上限，正数按本轮累计执行；不再固定 8 次模型调用、8 个生成任务或 120 秒视频。积分上限仍必填且大于 0，实际报价在任务创建与预留积分前校验，时长必须符合所选模型的实际能力。失败事件保留具体错误和已有任务的 `taskId`、`nodeId`、`status`；媒体结果的 `phase` 区分 `admission` 与 `completion`，`taskSubmitted` 表达是否已提交。模型应报告错误，不能自行删减提示词或自动重试收费生成。
- 必须有当前用户已保存的画布。首轮摘要最多取前 80 个节点；`canvas_get_state` 可按 `offset` 每页读取 40 个节点、资产可引用状态及相关连线，按 `nodeIds` 精读最多 8 个节点（正文每字段最多 16000 字符），通过 `hasMore` / `nextOffset` 和字段 `Truncated` 判断是否完整。分镜表包含镜头、角色节点与资产绑定；摘要每页最多 20 行，精读每次 1 行，可用 `storyboardOffset` 翻页；单行叙事文本累计最多 24000 字符，角色 / 绑定各最多 16 项。上下文不含媒体 URL、任意元数据或未同步修改；节点名称不等于图像视觉识别。普通任务重试接口不能重试 Agent 任务。
- `GET /agent/runs/:id` 返回运行信息；`POST /agent/runs/:id/cancel` 取消当前运行及活动子任务；`POST /agent/runs/:id/approvals/:approvalId/decision` 接受 `{"decision":"approve"|"reject","reason":"..."}`，审批决定幂等且服务端校验归属。
- `GET /agent/runs/:id/events` 返回 `agent_event` 和首次 / 状态版本变化时的紧凑 `run_snapshot` SSE；无变化时只发送 heartbeat。事件 `Seq` 在运行内递增；支持 `?after=` / `Last-Event-ID`，游标不是运行 ID。`cleanupPending: true` 时即使运行已进入终态也会继续推送，直到后台收尾完成。前端应以快照恢复状态，代理只对这一精确路径关闭缓冲。
- `generation_task_created` 携带 `canvasId`、`nodeId`、`taskId`、`title`、`mode`、`referenceNodeIds`。草稿、提交、画布工具写入，以及媒体成功 / 失败 / 取消的真实节点变更，均在画布写入与运行检查点的同一事务持久化 `canvas_updated`。节点已删除或换任务时不伪造更新；`run_failed` 本身不代表节点媒体任务失败。
- 未注册 Agent 能力的节点不阻断整张画布读取：摘要和 `canvas_get_state` 仅返回基础信息，并标记 `agentSupported: false` 与原因；不暴露任意 metadata，不授予该类型的创建、修改、连线或媒体引用能力。
- `approval.preview` 和 `canvas_updated.actions` 是服务端根据同一解析、快照与 Capability 规划流程生成的解释信息，不是授权凭证。审批卡片明确列出新增/修改节点、节点类型、修改字段、名称变化和连线两端；执行事件保存同样的可读信息，供历史消息显示和点击定位。实际写入仍重新校验用户归属、`snapshotHash`、Capability、节点锁、预算和审批 `callHash`。
- `canvas_updated` 包含 `canvasId`、`operation`、`callId`、`actions`、可选的 `preview`/`text` 和 `canvasPatch`。`canvasPatch` 为 `{ canvasId, updatedAt, nodes: [{ before, after }], connections: [{ before, after }] }`；新增对象的 `before` 为 `null`，仅包含有变化的节点和连线。当前工具不开放删除。节点 action 保存操作、节点 ID、执行前标题、类型、修改字段和可选的修改后标题；引用 action 同时保存来源与目标节点 ID、标题和类型，不要求前端从内部 ID 猜测对象。`callId` 用于合并同一画布操作的工具完成消息。
- 前端对增量按 40ms 窗口合批，三方合并远端基线、当前 Store 和编辑器，正常完成 / 失败无需全量 GET；保留无关节点编辑、拖动与视口，同字段冲突、删除或新任务绑定不强行覆盖。只有事件缺口、断流、增量冲突或没有增量的事件源需要全量校准，同一画布协调器最多每秒发起一次，单请求在途，期间重复通知合并为一次尾随校准。已识别增量协议后，相邻 `tool_failed` / `run_failed` 不重复触发整图刷新。
- Agent 创建 / 续聊请求在客户端先持久化完整正文、幂等键、父运行和消息 ID，再提交；网络超时或响应丢失只允许用同一正文和 key 有界重放，不能换 key 生成新收费轮次。客户端区分“服务端已明确返回错误”和“未收到服务端确认”，不再把 HTTP 409/500 一律描述成请求未确认。待确认记录损坏时对话暂停发送，不把它当成“从未提交”。
- 生成按钮与提交入口共用节点任务状态：排队 / 运行中不可重复生成，终态解除任务锁，历史 `taskId` 不永久禁用。聊天留痕保留节点名、引用与失败任务 ID，点击使用现有画布聚焦；已删除节点只提示，不自动重建。聊天缓存不重复保存增量中的完整节点正文。

Agent 的聊天列表缓存只负责 UI 恢复；运行、技能快照、审批、工具调用、子任务和事件均以服务端持久化状态为准。提交响应丢失时，客户端应使用同一幂等键重试，不生成新的提交。

Skills 的 `tool_completed` / `tool_failed` 事件附带 `skillId`、`skillName`（已启用技能）和 `path`；空路径表示列目录，不表示已读取文件。目录结果中的 `entryPath` 固定为 `SKILL.md`，`files` 为本轮固定快照的可读路径；Agent 先读取入口，再按入口引用读取必要文件。同一运行内同技能同路径只允许请求一次（包括不存在的路径），重复请求返回工具失败和继续执行指引，状态随运行持久化。模型初始上下文只包含技能版本、哈希、入口和可读文件清单，不包含技能正文。

模型任务失败的 `run_failed` 事件保留 `taskId`，并提供安全分类 `reason`：`model_connection_reset`、`model_request_timeout`、`model_connection_refused` 或 `model_task_failed`。`text` 不透传原始上游错误，避免泄露地址和凭证；前端用事件类型而非摘要关键词判断工具成功 / 失败。失败不会触发自动付费重试。

## 管理员支付订单

`GET /api/admin/payments/orders` 需要管理员权限，支持 `status`、`keyword`、`page`、`pageSize`。关键词匹配订单号、渠道交易号、用户名称、用户名或邮箱，也支持完整用户 ID 精确匹配。用户名和邮箱搜索忽略大小写；状态过滤同时生效，返回匹配总数和当前页订单。

每条管理员列表订单在原有字段之外包含 `user: { id, username, displayName, email }`，由当前页用户 ID 批量读取；用户不存在时返回 `user: null`，保留原 `userId` 与历史订单。此身份摘要仅用于管理员订单列表，不添加到普通用户支付接口或支付状态同步响应。

后台支付订单列表展示用户身份，点击名称打开用户详情；订单详情提供完整订单号、渠道交易号、用户 ID 和各阶段时间。同步支付状态与关闭订单位于更多菜单，关闭订单仍需确认。

## 管理员系统渠道

`POST /api/admin/channels/:id/duplicate` 需要管理员权限，会复制指定系统渠道的连接配置、加密凭证、请求头、模型和价格档，生成新的渠道与模型 ID；复制渠道名称自动追加“ - 副本”。原渠道及其前台供应线路不受影响。

## 信封

成功：

```json
{ "code": 0, "data": {}, "msg": "ok" }
```

失败：HTTP status 与 `code` 都不是成功；`reason` 是稳定机器可读原因。

```json
{ "code": 40301, "data": null, "msg": "账号素材数量已达到 100 个上限", "reason": "quota_exceeded" }
```

`code === 0` 才是业务成功。HTTP 200 但 `code !== 0` 必须当失败。前端判断类型用 `ApiError.reason` / `ApiError.code`，不要解析 `msg`。

## 错误码

`code` 默认等于 HTTP 状态。需要区分同一状态的不同原因时，使用 `status * 100 + n`。没有单独的 1001/2001 号段，以免和 HTTP 状态、现有 42901 以及重试判断打架。

| code | HTTP | reason | 含义 |
| --- | --- | --- | --- |
| 0 | 200 | — | 成功 |
| 400 | 400 | `invalid_argument` | 请求不合法 |
| 401 | 401 | `unauthorized` | 未登录 |
| 403 | 403 | `forbidden` | 无权限 |
| 404 | 404 | `not_found` | 资源不存在 |
| 409 | 409 | `conflict` | 冲突 |
| 429 | 429 | `rate_limited` | 限流（未细分） |
| 500 | 500 | `internal` | 内部错误 |
| 502 | 502 | `bad_gateway` | 上游失败 |
| 503 | 503 | `unavailable` | 暂时不可用 |
| 504 | 504 | `timeout` | 超时 |
| 40301 | 403 | `quota_exceeded` | 账号配额用尽（不自动重试） |
| 40901 | 409 | `conflict` | 幂等冲突 |
| 42901 | 429 | `rate_limited` | 请求限流（可带 Retry-After） |

模型错误把已有字符串码放进 `reason`（如 `model_capability_not_supported`），`code` 仍为 400。

常量：后端 `service/error_codes.go`，前端 `web/src/services/api/error-codes.ts`。

## 用户自己修改显示名称

`PATCH /api/auth/display-name` 仅接受 `{ "displayName": "我的显示名称" }`，账号取自当前登录 Cookie，只能修改本人。额外字段（包括登录用户名、用户 ID、角色、密码）直接返回 400。名称去除首尾空白后须为 1-40 个 Unicode 字符，支持中文、空格与同名，不允许换行或控制字符；并发修改冲突返回 409，未登录返回 401，停用账号返回 403。每账号每 10 分钟限 10 次请求，超限返回 429 和 `Retry-After`。

成功返回 `data.user`，包含本人公开第三方身份，响应禁止缓存。仅更新 `display_name` 和 `updated_at`；登录用户名、邮箱、密码、Linux.do 身份绑定、角色、积分、任务和素材归属不变，原会话继续有效。登录仍使用原用户名或邮箱及原密码，显示名称不是登录账号。相同名称为无操作；修改和 `user.display_name.update_self` 审计同事务，记录 `previousDisplayName` 与 `displayName`，任一写入失败均回滚。

入口为“头像菜单 → 账号设置 → 显示名称”，登录用户名只读。保存成功后同步更新当前账号的显示名称并失效会话缓存，不清空用户 scope 或重新初始化画布；旧会话请求迟到时重新读取，切换账号后的响应不会修改新账号状态。原先误加的自助登录用户名接口 `/api/auth/username` 已移除，管理员改登录用户名的接口保持不变。

## 管理员修改用户名

`PATCH /admin/users/:id` 接受可选 `username`。省略时保留原用户名；提供时去除首尾空白，校验 3-32 位字母、数字、下划线或连字符。空值或格式错误返回 400，与其他账号重名（不区分大小写）返回 409；目标不存在返回 404。接口及 service 均要求管理员身份。

改名后使用新用户名和原密码登录，邮箱登录不受影响。仅改名不更换用户 ID，不重置积分余额、个人统计、任务、素材或登录会话。若同时提交新密码，则撤销该用户的旧会话。用户名修改和 `user.update` 审计在同一事务内完成，审计元数据包含 `previousUsername` 与 `username`；任一写入失败都会回滚。

后台入口为“用户管理 → 编辑用户 → 用户名”。编辑当前管理员本人时，前端同步更新当前用户展示信息；登录时间写入只更新对应字段，不写回可能已经过时的用户名。

## 管理员找回用户密码

后台“用户管理 → 重置密码”可手动设置新密码，或使用浏览器安全随机源生成 24 位随机密码。不需要用户旧密码，不依赖邮件服务，不读取原密码明文；不会自动启用已停用的账号。密码操作只提交 `PATCH /admin/users/:id` 的 `password` 字段，不携带用户名、角色或积分修改。

密码按原值保存（不裁剪空白），至少 8 个字符，UTF-8 编码最多 72 字节。后端仅存储 bcrypt 哈希，并在同一事务内撤销目标用户所有旧会话、写入 `user.update` 审计。审计仅记录 `passwordChanged` 和 `sessionsRevoked` 标记，不包含新旧密码或哈希；接口响应禁止缓存。管理员重置自己的密码时同时清除会话 Cookie，弹窗完成后返回登录页。

保存成功后的新密码只保留在弹窗内存中，支持显式显示和复制，关闭即清除，不保存到 localStorage 或服务器明文字段。复制会写入系统剪贴板，请通过可信方式交付本人。未启用邮件服务的账号可由管理员按上述入口协助找回；已有“忘记密码”邮箱验证码流程保持不变。

## 管理统计

管理员统计端点使用同一组筛选参数：`from`、`to`、`userId`、`model`、`channelId`、`capability`。日期参数按 UTC 自然日解释，`to` 对调用方是包含当天；默认查询 30 天，最长 366 天。

| 端点 | 返回内容 |
| --- | --- |
| `GET /admin/analytics/overview` | KPI、逐日趋势、模型、渠道、个人和失败分类的完整总览 |
| `GET /admin/analytics/models` | 按逻辑模型和能力聚合的明细 |
| `GET /admin/analytics/channels` | 按最终归属渠道聚合的明细 |
| `GET /admin/analytics/users` | 每个人的完整总账，以及截至区间末尾的 DAU、WAU、MAU |
| `GET /admin/analytics/export.csv` | 每个人一行的 UTF-8 BOM CSV，内含模型、渠道、逐日 JSON 明细 |

统计口径分为三套事实，不能相互代替：

- **任务事实**：文/图/视/音任务、排队/运行/成功/失败/取消、任务耗时、成功媒体和视频秒数。媒体与视频秒数只按成功任务计一次；历史视频任务缺失输入秒数时，最多从同任务日志回补一次。
- **逻辑请求事实**：请求成败、耗时和 Token。`poll`、`download` 不计为逻辑请求，避免轮询把调用量重复放大。
- **账单事实**：仅已结算订单计入积分消耗；按结算时间落入区间。上游费用是按已配置价格估算的微单位值，必须结合 `costAvailable` 与 `currency` 使用。

`users[]` 精确到账号，除个人总账外还包含 `models[]`、`channels[]`、`daily[]`。每日明细覆盖登录、文/图/视/音任务、各任务状态、请求成败、图/视/音产量、视频秒数、Token、积分、估算费用、Agent 消息、画布活跃、素材和资源。登录本身会计入活跃日，因此没有生成任务但在区间内登录过的账号仍可出现。

模型、渠道及账单通过 `task_id` 归一。渠道优先采用已结算订单渠道，其次采用成功请求渠道，再其次采用失败请求渠道；无系统渠道 ID 的记录显示为“本地、自定义或未关联”，不会被武断归类为某一个渠道。

## 个人积分统计

`GET /wallet` 除账户和分页流水外返回当前登录用户的 `consumption`。`todayMicrocredits`、`yesterdayMicrocredits`、`weekMicrocredits` 和 `monthMicrocredits` 分别表示今日、昨日、本周一至今日和本月一日至今日的已结算积分消耗；`daily[]` 从本月一日连续返回到今日，元素包含 `day`、`amountMicrocredits` 和结算次数 `count`。

个人统计统一按 `Asia/Shanghai` 自然日计算，只汇总该用户的 `consume` 积分流水，不包含冻结、充值或退款，也不受 `type`、`page`、`pageSize` 流水查询参数影响。金额单位均为微积分，`1_000_000` 微积分等于 `1` 积分。

## 资源上传

普通上传使用 `POST /api/resources` multipart；大文件通过 `POST /api/resources/uploads` 创建会话、`PUT /api/resources/uploads/:id/chunks/:index` 发送原始二进制分片、`POST /api/resources/uploads/:id/complete` 合并保存。三步都校验登录用户，会话不能跨账号使用。

开始会话接受 `X-Idempotency-Key`，也支持原有 JSON `idempotencyKey`；两处同时非空但不一致时返回 400。未提供时使用会话内生成的标识；需要跨会话去重时调用方必须复用同一个逻辑上传标识。服务端仅在相同用户范围复用资源，重试不会重复创建已就绪资源或重复计入日上传量。

每片严格匹配返回的大小合同，完整接收后才替换临时分片；不完整或超长的重试不能破坏已确认内容。当前浏览器最多并行发送 3 片，对瞬时失败最多尝试 3 次；鉴权、权限、大小等永久错误不自动重传，合并失败也不自动重开会话传整份文件。合并开始后不再接受分片改写，资源保存尝试结束后清理会话。会话只在当前进程内存中存在，重启不能断点续传；90 分钟过期会话在后续创建或访问会话时清理。

分片落库重试沿用分片大小合同，不套用普通 multipart 的单文件上限；每日上传及总空间仍重新校验和预留。失败与 pending 资源不计入已用空间，不能以已有失败记录为由跳过总空间检查；成功提交、失败释放预留。

上传响应新增 `Server-Timing`：普通上传含 `receive` / `store`，单片含 `receive`，合并成功路径含 `merge` / `store`。失败仅包含已执行的阶段，不保证鉴权失败或代理失败响应携带计时。仅暴露阶段与毫秒值，不包含密钥或存储 URL；计时不包含前置代理缓冲。

## 资源预览出口

`GET /api/resources/:id/file` 先校验登录态和资源归属。七牛 Kodo 配置绑定 CDN 域名且可用性探测成功时，默认返回 `307` 到五分钟有效的签名 CDN 地址，浏览器直接接收媒体，不由业务服务器转发视频流；阿里云 OSS、腾讯 COS 的既有 CDN 跳转保持不变。重定向响应使用 `Cache-Control: private, no-store`，签名地址仅用于本次读取，不写入画布或浏览器持久配置。

`proxy=1` 仍显式使用同源代理，供截帧、编辑和需要 Blob 的操作读取。普通预览只复用已存在的用户隔离 Blob 缓存，不再因图片进入视口或视频开始播放而通过代理下载完整文件。七牛下载请求的 `download=1&filename=...` 映射到参与签名的 `attname`，预览不带附件参数。

七牛 CDN 可用性探测沿用两分钟缓存，缓存键不包含轮换的签名或附件文件名；失败不缓存为成功。CDN 返回 404/410 或暂时不可用时不跳转，保留源站读取、本地副本和自动补传路径；探测失败本身不会删除资源。未配置 CDN 的七牛、本地存储和私网 S3 的既有交付方式不变。需要跨域读取的播放器与编辑器仍要求 CDN 正确配置 CORS 和 Range 响应。

## 存储设置恢复

`GET /admin/settings/oss` 返回平台对象存储的非敏感配置。`credentialsRequireReset` 为 `true` 表示数据库中的加密凭据无法由当前后端数据目录的 `.settings-key` 解密，常见于只恢复 PostgreSQL、未同时恢复后端数据卷的场景。此时响应不会返回或伪装可用的 Secret，管理员必须重新填写当前厂商凭据，或切换到服务器本地存储后保存。

普通资源读写仍严格校验密文，不会使用无法解密的凭据。读取恢复状态本身不会改写数据库中的旧密文。

管理员可通过 `GET /admin/settings/oss/credentials` 显式读取当前平台凭据。该接口单独执行管理员鉴权和限流，响应禁止缓存，并写入不含明文的管理员审计记录；普通 `GET /admin/settings/oss` 始终保持脱敏。若恢复数据库时遗失原 `.settings-key`，旧密文在密码学上不可恢复，该接口返回冲突提示，重新填写 SecretKey 并保存后才能读取。
