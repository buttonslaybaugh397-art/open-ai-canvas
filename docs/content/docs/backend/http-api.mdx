# HTTP API 合同

路径前缀是 `/api`。前后端一起发布，不按 `/api/v1`、`/api/v2` 做路径版本。不兼容变更随版本一起改接口和调用方。

机器可读规范：运行中的 `GET /api/openapi.yaml`，源文件 `backend/internal/handler/openapi.yaml`。前端 TypeScript 仍走 `web/src/services/api` 的 `http`，不从 OpenAPI 生成客户端。

## 账号文件容量

`GET /api/resources/storage-usage` 只核算登录 Cookie 对应账号，返回 `data.usage`：

```json
{
  "usedBytes": 100,
  "totalBytes": 21474836480,
  "resourceBytes": 60,
  "sessionBytes": 10,
  "pendingDeletionBytes": 30,
  "checkedAt": "2026-09-15T01:02:03Z"
}
```

`usedBytes` 是三个分项之和；`totalBytes` 取运行时账号文件容量策略。资源按 provider、endpoint、bucket、objectKey 去重，本地文件以实际文件长度为准，S3 / OSS / COS 查询源站 HEAD，七牛查询管理 API 的 `fsize`，不使用 CDN 长度或数据库声明的 `size` 代替实际占用。资源表和物理删除 outbox 在同一数据库快照读取，避免交接窗口漏计。

回收站仍持有文件，继续占用；失败资源留下的文件也计入。彻底删除后，待清理对象只有物理消失才释放容量。明确不存在的对象计零，权限不足、网络或数据库失败、长度缺失、越界路径均返回真实错误，不返回部分合计或零用量。读取不删除文件、不修改资源状态。

核算范围是当前归属记录指向的资源原件和 Agent 会话附件，不是整台服务器的磁盘使用量；播放派生缓存、临时上传分片、未归属文件、数据库和结构化 JSON 不纳入此配额。全站后台资源表的数据库汇总仍是另一种口径，不替代本接口。管理员用户详情的 `storedFileBytes` 使用相同实测口径，文件核验最多等待 3 秒；失败时仅该字段返回 `null` 并提供 `fileStorageError`，其他账号详情照常读取，页面不展示伪造的零容量进度。

普通读取允许最多 30 秒的云端元数据缓存；`?refresh=1` 强制重新核验，`checkedAt` 表示本次合计中最早的文件观测时间。每账号每分钟最多 30 次读取，其中强制重算最多 6 次。一次核算最长 30 秒，每次最多 4 个对象并发，单服务实例最多 4 次核算同时执行；超时明确失败，不把未检查的文件算零。大账号冷核验耗时取决于对象数及存储延迟，发布前须用实际账号验收。

素材库每分钟刷新，待物理清理期间每 5 秒刷新，后台标签页不定时轮询。上传、彻底删除、批量删除和清空回收站后失效容量缓存，部分删除失败也触发刷新；手动重算按钮直接回源。查询按用户 ID 隔离并传递取消信号；刷新失败且存在旧结果时标记上次统计，不能冒充最新值。

上传额度校验同样核验实际文件，并绕过读缓存；网络核验在预留锁外完成，进入锁后复核归属快照，有变化则有限重试，再叠加本实例在途上传预留量。无法确认占用时拒绝本次上传，不影响读取原文件。现有多实例上传预留协议未改变，不宣称本改动新增了跨实例原子预留。每日上传量是独立的 UTC 当日累计流量，删除文件不会清零或返还每日额度。

本项无数据库表结构迁移、不回填历史文件。前后端需同版本发布，新前端会拒绝缺少分项和核验时间的旧统计响应；回滚应同时回退接口与页面。与任务恢复功能一同发布时仍须执行其 Schema 11 迁移。

## 失败视频任务恢复

`POST /api/tasks/:id/query-provider` 校验登录用户的任务归属；`POST /api/admin/api-logs/:id/query-task` 额外校验管理员权限及日志与任务归属，并记录审计。两者只接受已有上游任务 ID 的失败视频任务，使用同一渠道适配器查询，绝不创建新的上游生成。

成功信封的 `data` 为 `{ task, providerStatus, recovered, pollingResumed, billingSettled }`：

- 上游仍为 pending / processing：持久化恢复轮询，返回 `task.status=running`、`pollingResumed=true`、`recovered=false`，此时不扣费；原输入配置、上游 ID 和订单保持不变。
- 已取得并保存结果：返回 `task.status=succeeded`、`recovered=true`、`pollingResumed=false`；退款订单按原订单恢复结算，其他订单沿用原结算路径。
- 上游失败、协议不可用、资源保存或计费失败继续返回真实错误；并发人工恢复返回冲突，不用假成功绕过校验。

任务详情和列表摘要新增可选 `providerRecoveryAt`。前端以此识别失败后的恢复世代，拒绝迟到的旧失败状态。用户已打开画布中绑定的失败视频任务每 5 秒读取一次本用户任务状态，恢复运行后接回正常任务观察，成功后消费结果；不依赖管理员浏览器的本地事件，也不要求刷新。该机制是短轮询，不是 WebSocket 推送；离线、后台节流和网络错误可能延迟更新。

## 管理员支付订单

`GET /api/admin/payments/orders` 需要管理员权限，支持 `status`、`keyword`、`page`、`pageSize`。关键词匹配订单号、渠道交易号、用户名称、用户名或邮箱，也支持完整用户 ID 精确匹配。用户名和邮箱搜索忽略大小写；状态过滤同时生效，返回匹配总数和当前页订单。

每条管理员列表订单在原有字段之外包含 `user: { id, username, displayName, email }`，由当前页用户 ID 批量读取；用户不存在时返回 `user: null`，保留原 `userId` 与历史订单。此身份摘要仅用于管理员订单列表，不添加到普通用户支付接口或支付状态同步响应。

后台支付订单列表展示用户身份，点击名称打开用户详情；订单详情提供完整订单号、渠道交易号、用户 ID 和各阶段时间。同步支付状态与关闭订单位于更多菜单，关闭订单仍需确认。

## 信封

成功：

```json
{ "code": 0, "data": {}, "msg": "ok" }
```

失败：HTTP status 与 `code` 都不是成功；`reason` 是稳定机器可读原因。

```json
{ "code": 40301, "data": null, "msg": "账号素材数量已达到 100 个上限", "reason": "quota_exceeded" }
```

`code === 0` 才是业务成功。HTTP 200 但 `code !== 0` 必须当失败。前端判断类型用 `ApiError.reason` / `ApiError.code`，不要解析 `msg`。

## 错误码

`code` 默认等于 HTTP 状态。需要区分同一状态的不同原因时，使用 `status * 100 + n`。没有单独的 1001/2001 号段，以免和 HTTP 状态、现有 42901 以及重试判断打架。

| code | HTTP | reason | 含义 |
| --- | --- | --- | --- |
| 0 | 200 | — | 成功 |
| 400 | 400 | `invalid_argument` | 请求不合法 |
| 401 | 401 | `unauthorized` | 未登录 |
| 403 | 403 | `forbidden` | 无权限 |
| 404 | 404 | `not_found` | 资源不存在 |
| 409 | 409 | `conflict` | 冲突 |
| 429 | 429 | `rate_limited` | 限流（未细分） |
| 500 | 500 | `internal` | 内部错误 |
| 502 | 502 | `bad_gateway` | 上游失败 |
| 503 | 503 | `unavailable` | 暂时不可用 |
| 504 | 504 | `timeout` | 超时 |
| 40301 | 403 | `quota_exceeded` | 账号配额用尽（不自动重试） |
| 40901 | 409 | `conflict` | 幂等冲突 |
| 42901 | 429 | `rate_limited` | 请求限流（可带 Retry-After） |

模型错误把已有字符串码放进 `reason`（如 `model_capability_not_supported`），`code` 仍为 400。

常量：后端 `service/error_codes.go`，前端 `web/src/services/api/error-codes.ts`。

## 生成任务的自定义请求头

`POST /api/tasks` 的 `input.config.headers` 为可选数组，每项仅包含字符串 `name`、`value`；省略、`null` 或空数组表示无自定义头。统一校验重复名称、控制字符、大小限制和系统管理的头部，不能用自定义头覆盖登录凭据、Host、Cookie 或转发边界。文本、图片、视频、音频和工具任务均保留所选自定义渠道的请求头；系统模型执行仍从服务端渠道配置取值。

任务持久化时，非空头值与 API Key 一样使用 `.settings-key` 加密，执行或恢复时解密，名称及 API 形状不变。无效结构或损坏密文直接失败，公开任务响应不返回 `config`。保护只针对根级 `config.headers`，不改写工具参数 schema 或工作流中的同名字段。

没有数据库表结构迁移，也不自动改写历史记录。发布时保留 `.settings-key`；新版写入的加密请求头任务不能交给旧版 worker，回滚前应先排空这些任务，不通过删除密钥或重新提交收费任务处理。

## 用户自己修改显示名称

`PATCH /api/auth/display-name` 仅接受 `{ "displayName": "我的显示名称" }`，账号取自当前登录 Cookie，只能修改本人。额外字段（包括登录用户名、用户 ID、角色、密码）直接返回 400。名称去除首尾空白后须为 1-40 个 Unicode 字符，支持中文、空格与同名，不允许换行或控制字符；并发修改冲突返回 409，未登录返回 401，停用账号返回 403。每账号每 10 分钟限 10 次请求，超限返回 429 和 `Retry-After`。

成功返回 `data.user`，包含本人公开第三方身份，响应禁止缓存。仅更新 `display_name` 和 `updated_at`；登录用户名、邮箱、密码、Linux.do 身份绑定、角色、积分、任务和素材归属不变，原会话继续有效。登录仍使用原用户名或邮箱及原密码，显示名称不是登录账号。相同名称为无操作；修改和 `user.display_name.update_self` 审计同事务，记录 `previousDisplayName` 与 `displayName`，任一写入失败均回滚。

入口为“头像菜单 → 账号设置 → 显示名称”，登录用户名只读。保存成功后同步更新当前账号的显示名称并失效会话缓存，不清空用户 scope 或重新初始化画布；旧会话请求迟到时重新读取，切换账号后的响应不会修改新账号状态。原先误加的自助登录用户名接口 `/api/auth/username` 已移除，管理员改登录用户名的接口保持不变。

## 管理员修改用户名

`PATCH /admin/users/:id` 接受可选 `username`。省略时保留原用户名；提供时去除首尾空白，校验 3-32 位字母、数字、下划线或连字符。空值或格式错误返回 400，与其他账号重名（不区分大小写）返回 409；目标不存在返回 404。接口及 service 均要求管理员身份。

改名后使用新用户名和原密码登录，邮箱登录不受影响。仅改名不更换用户 ID，不重置积分余额、个人统计、任务、素材或登录会话。若同时提交新密码，则撤销该用户的旧会话。用户名修改和 `user.update` 审计在同一事务内完成，审计元数据包含 `previousUsername` 与 `username`；任一写入失败都会回滚。

后台入口为“用户管理 → 编辑用户 → 用户名”。编辑当前管理员本人时，前端同步更新当前用户展示信息；登录时间写入只更新对应字段，不写回可能已经过时的用户名。

## 管理员找回用户密码

后台“用户管理 → 重置密码”可手动设置新密码，或使用浏览器安全随机源生成 24 位随机密码。不需要用户旧密码，不依赖邮件服务，不读取原密码明文；不会自动启用已停用的账号。密码操作只提交 `PATCH /admin/users/:id` 的 `password` 字段，不携带用户名、角色或积分修改。

密码按原值保存（不裁剪空白），至少 8 个字符，UTF-8 编码最多 72 字节。后端仅存储 bcrypt 哈希，并在同一事务内撤销目标用户所有旧会话、写入 `user.update` 审计。审计仅记录 `passwordChanged` 和 `sessionsRevoked` 标记，不包含新旧密码或哈希；接口响应禁止缓存。管理员重置自己的密码时同时清除会话 Cookie，弹窗完成后返回登录页。

保存成功后的新密码只保留在弹窗内存中，支持显式显示和复制，关闭即清除，不保存到 localStorage 或服务器明文字段。复制会写入系统剪贴板，请通过可信方式交付本人。未启用邮件服务的账号可由管理员按上述入口协助找回；已有“忘记密码”邮箱验证码流程保持不变。

## 管理统计

管理员统计端点使用同一组筛选参数：`from`、`to`、`userId`、`model`、`channelId`、`capability`。日期参数按 UTC 自然日解释，`to` 对调用方是包含当天；默认查询 30 天，最长 366 天。

| 端点 | 返回内容 |
| --- | --- |
| `GET /admin/analytics/overview` | KPI、逐日趋势、模型、渠道、个人和失败分类的完整总览 |
| `GET /admin/analytics/models` | 按逻辑模型和能力聚合的明细 |
| `GET /admin/analytics/channels` | 按最终归属渠道聚合的明细 |
| `GET /admin/analytics/users` | 每个人的完整总账，以及截至区间末尾的 DAU、WAU、MAU |
| `GET /admin/analytics/export.csv` | 每个人一行的 UTF-8 BOM CSV，内含模型、渠道、逐日 JSON 明细 |

统计口径分为三套事实，不能相互代替：

- **任务事实**：文/图/视/音任务、排队/运行/成功/失败/取消、任务耗时、成功媒体和视频秒数。媒体与视频秒数只按成功任务计一次；历史视频任务缺失输入秒数时，最多从同任务日志回补一次。
- **逻辑请求事实**：请求成败、耗时和 Token。`poll`、`download` 不计为逻辑请求，避免轮询把调用量重复放大。
- **账单事实**：仅已结算订单计入积分消耗；按结算时间落入区间。上游费用是按已配置价格估算的微单位值，必须结合 `costAvailable` 与 `currency` 使用。

`users[]` 精确到账号，除个人总账外还包含 `models[]`、`channels[]`、`daily[]`。每日明细覆盖登录、文/图/视/音任务、各任务状态、请求成败、图/视/音产量、视频秒数、Token、积分、估算费用、Agent 消息、画布活跃、素材和资源。登录本身会计入活跃日，因此没有生成任务但在区间内登录过的账号仍可出现。

模型、渠道及账单通过 `task_id` 归一。渠道优先采用已结算订单渠道，其次采用成功请求渠道，再其次采用失败请求渠道；无系统渠道 ID 的记录显示为“本地、自定义或未关联”，不会被武断归类为某一个渠道。

## 个人积分统计

`GET /wallet` 除账户和分页流水外返回当前登录用户的 `consumption`。`todayMicrocredits`、`yesterdayMicrocredits`、`weekMicrocredits` 和 `monthMicrocredits` 分别表示今日、昨日、本周一至今日和本月一日至今日的已结算积分消耗；`daily[]` 从本月一日连续返回到今日，元素包含 `day`、`amountMicrocredits` 和结算次数 `count`。

个人统计统一按 `Asia/Shanghai` 自然日计算，只汇总该用户的 `consume` 积分流水，不包含冻结、充值或退款，也不受 `type`、`page`、`pageSize` 流水查询参数影响。金额单位均为微积分，`1_000_000` 微积分等于 `1` 积分。

## 资源上传

普通上传使用 `POST /api/resources` multipart；大文件通过 `POST /api/resources/uploads` 创建会话、`PUT /api/resources/uploads/:id/chunks/:index` 发送原始二进制分片、`POST /api/resources/uploads/:id/complete` 合并保存。三步都校验登录用户，会话不能跨账号使用。

开始会话接受 `X-Idempotency-Key`，也支持原有 JSON `idempotencyKey`；两处同时非空但不一致时返回 400。未提供时使用会话内生成的标识；需要跨会话去重时调用方必须复用同一个逻辑上传标识。服务端仅在相同用户范围复用资源，重试不会重复创建已就绪资源或重复计入日上传量。

每片严格匹配返回的大小合同，完整接收后才替换临时分片；不完整或超长的重试不能破坏已确认内容。当前浏览器最多并行发送 3 片，对瞬时失败最多尝试 3 次；鉴权、权限、大小等永久错误不自动重传，合并失败也不自动重开会话传整份文件。合并开始后不再接受分片改写，资源保存尝试结束后清理会话。会话只在当前进程内存中存在，重启不能断点续传；90 分钟过期会话在后续创建或访问会话时清理。

分片落库重试沿用分片大小合同，不套用普通 multipart 的单文件上限；每日上传及总空间仍重新校验和预留。失败与 pending 资源不计入已用空间，不能以已有失败记录为由跳过总空间检查；成功提交、失败释放预留。

上传响应新增 `Server-Timing`：普通上传含 `receive` / `store`，单片含 `receive`，合并成功路径含 `merge` / `store`。失败仅包含已执行的阶段，不保证鉴权失败或代理失败响应携带计时。仅暴露阶段与毫秒值，不包含密钥或存储 URL；计时不包含前置代理缓冲。

## 视频兼容播放副本

`POST /api/resources/:id/playback` 无请求体，需要登录且只能操作本人 `kind=video`、`status=ready` 的资源；缺失或跨账号返回 404，非视频返回 400，原件未就绪返回 409。成功信封为 `{ "code": 0, "data": { "resource": {} }, "msg": "ok" }`，`resource` 保持现有资源结构，通过 `playbackStatus`、`playbackObjectKey`、`playbackError` 表达处理进度。

浏览器解码错误 3/4 后可调用一次：空状态或 `none` 可抢占转码，包括 H.264 特殊 profile、像素格式及非 MP4 容器；`processing`、`ready` 直接复用，`failed` 是终态，不自动重试。`processing` 可通过 `GET /api/resources/:id` 轮询；`ready` 使用 `GET /api/resources/:id/file?variant=playback`。前端最多等待 5 分钟，这只是停止当前预览等待，不取消最长 15 分钟的后台处理。FFmpeg 缺失或配置路径不可执行也明确返回资源 `failed`，错误说明可安全显示，不把失败伪装成 `none`。此时 HTTP 200 表示状态查询/创建请求已处理，不代表转码成功。

本地与 OSS/COS/Kodo/S3 原件均可按需适配。自动上传探测和启动补判仍仅处理本地视频，不批量下载云端原件。按账号使用 `request.resourceImportPerMinute` 频控；全局最多 2 路后台任务，协调器不可用返回 503，并发占满返回 429 和 `Retry-After`，不无限排队。PostgreSQL 多实例复用 Redis 并发租约，数据库条件更新确保同一资源只有一个 claim；独立输出键同时作为处理标识，过期 worker 不得覆盖新状态或其他 Resource 字段。仅超过 16 分钟的 processing 记录才可失效，启动检查或本人资源查询会将其标记 failed，不在实例启动时重置其他实例的活跃工作。

读取原件复用安全资源层、私网上游精确白名单和当前资源存储凭据，下载支持取消，落盘后才启动 FFmpeg。整个后台任务最多 15 分钟，输入和输出分别限 1GiB；服务关闭会取消任务并清理临时文件。FFmpeg 使用现有 `CANVAS_FFMPEG_PATH`，未配置时从 PATH 查找；只允许 `file` 协议和 MOV/MP4、Matroska/WebM、AVI、FLV、MPEG-TS、MPEG、Ogg 容器，禁用 MOV 外部数据引用，不接受 HLS、DASH、concat 等嵌套清单。FFmpeg 不直接读取用户 URL；原件和副本读取被限制在各自数据目录内。

输出为 H.264 Main、yuv420p、AAC 双声道、faststart MP4。只有本次 FFmpeg 成功退出、输出校验通过，才从临时文件原子发布为唯一副本并条件更新 ready；不能仅因旧 `.mp4` 文件含 H.264 头就复用半成品。原件不改写，失败响应和持久错误不暴露凭据、原件地址或本机路径。未新增数据库列；多实例提供同一资源时需共享后端 playback 数据目录，否则无法读取另一个实例生成的本地副本。

播放副本是额外的本地磁盘占用，不计入原件 `Resource.size` 或当前账号已用资源空间；单个副本最多 1GiB。临时输入/输出在成功、失败和正常取消时清理，但已发布副本目前不随原资源删除自动回收，进程被强制终止也可能留下临时目录。部署需要单独预留和监控 playback 卷空间；引用感知的孤立副本与崩溃临时目录回收尚待实现，不能用直接删除在用副本的方式替代资源删除校验。

`variant=playback` 的 ready 副本在服务层优先选择，不受原件 Provider 影响，也不因 `direct=1` 跳回云端原件；支持 Range、If-Range 和副本独立 ETag。`download=1` 优先级更高，始终下载原件，保留原件文件名及此前的 CDN/代理下载路径。尚无 ready 副本时 file 仍按原件读取规则处理。

## 失效资源引用修复

`POST /api/resources/:id/repair-references` 需要登录，请求体为 `{ "replacementResourceId": "新资源ID" }`，路径 `id` 是旧资源 ID。两个 ID 必须非空、有效且不同；替换资源必须属于当前用户并处于 `ready`。旧资源可以不存在，或属于当前用户且处于 `failed` / `deleted`；旧记录属于其他账号时返回 403，旧记录仍为 `ready` / `pending` 或其他状态时返回 409。替换记录不存在或不属于当前账号返回 404，替换记录未就绪返回 409。

由于修复需要扫描账号已有文档，接口按运行时策略 `request.assetWritePerMinute` 单独对账号限流；超限返回 429 和 `Retry-After`。请求体上限为 1KB。

接口在存储锁下读取当前用户已有的全部 Asset 与 Canvas JSON，包括浏览器尚未加载的画布；仅递归改写 `storageKey`、`resourceKey`、`content`、`dataUrl`、`url`、`coverUrl` 中完整的 `resource:旧ID` 或已知 `/api/resources/旧ID/file`、`/api/public/resources/旧ID/file[/文件名]` HTTP(S) / 根相对文件地址。URL 查询参数与片段原样保留，不做正文子串替换，不改其他字段、其他用户、项目、任务或资源记录，也不删除或修改旧 Resource。

Asset 与 Canvas 改写同事务提交；仓储重新核对资源归属和状态，以完整原 JSON 和 `updated_at` 做 CAS，仅更新匹配文档的引用字段。作为基础设施修复，JSON 内的 `updatedAt` 和数据库 `updated_at` 均保持原值，前端可只改写已确认同步快照中的引用而不接受其他内容。并发变更返回 409，任一写入失败则全部回滚；正常素材与画布保存校验不变。JSON 解析、内嵌媒体、文档大小和新增结构化存储用量仍强校验。

成功统一返回 `{ "code": 0, "data": { "repaired": true }, "msg": "ok" }`。不存在匹配的已持久化记录时也是幂等成功，支持前端刚创建、尚未上传的 Asset；重复修复不会新增记录或重复改写。前端先确认旧资源失效，再使用旧 `resource:ID` 作为上传幂等标识上传本地文件，取得 ready 的新 ID 后调用本接口；成功后同步本地引用，按 Asset 先于 Canvas 的顺序保存。失败不得宣称已修复或绕过后续保存校验。

资源记录探测使用 `GET /api/resources/:id`；仅记录缺失返回 404，数据库故障返回真实服务端错误，避免误触发补传。浏览器按本轮待保存实体去重探测，明确缺失后只读取当前账号本地缓存，不再下载已知缺失的资源。找不到本地副本时明确报错；不根据网络错误、权限错误或 pending 状态创建替代资源。此流程不检测 ready 记录背后的物理对象是否被外部删除。

## 资源下载

`GET /api/resources/:id/file?direct=1&download=1&filename=编码后的文件名` 使用登录 Cookie 鉴权，返回二进制而非 JSON 信封。`filename` 是可选下载名称，需 URL 编码；同源响应通过标准 `Content-Disposition` 编码文件名。Range 请求仍支持 206，不需要浏览器先把整个文件读取成 Blob。

带七牛 CDN 配置的显式下载可重定向到含 `attname` 的短时签名地址；其他尚未实现附件响应头覆盖的存储继续同源流式传输。预览路径与显式 `proxy=1` 保持原语义；签名重定向禁止缓存。下载页面命中当前会话 Blob URL 时直接保存，未命中时交给浏览器下载管理器接收；这优化开始下载前的等待，不保证公网传输速率。

## 存储设置恢复

`GET /admin/settings/oss` 返回平台对象存储的非敏感配置。`credentialsRequireReset` 为 `true` 表示数据库中的加密凭据无法由当前后端数据目录的 `.settings-key` 解密，常见于只恢复 PostgreSQL、未同时恢复后端数据卷的场景。此时响应不会返回或伪装可用的 Secret，管理员必须重新填写当前厂商凭据，或切换到服务器本地存储后保存。

普通资源读写仍严格校验密文，不会使用无法解密的凭据。读取恢复状态本身不会改写数据库中的旧密文。

管理员可通过 `GET /admin/settings/oss/credentials` 显式读取当前平台凭据。该接口单独执行管理员鉴权和限流，响应禁止缓存，并写入不含明文的管理员审计记录；普通 `GET /admin/settings/oss` 始终保持脱敏。若恢复数据库时遗失原 `.settings-key`，旧密文在密码学上不可恢复，该接口返回冲突提示，重新填写 SecretKey 并保存后才能读取。
