# 在线更新与安全回退

管理后台的“系统配置 → 系统更新”只负责管理员鉴权、展示状态和发起操作。真正的 Docker、数据库备份与服务切换由宿主机上的 `open-ai-canvas-host-updater` 执行，业务后端不挂载 Docker Socket。

```text
管理员浏览器 → Backend 管理 API → 带 Token 的 Unix Socket → Host Updater → Docker Compose
```

## 安全更新顺序

1. 从 GitHub Releases 读取包含预览版在内的最高语义版本，并与 `.env` 中固定的 `CANVAS_IMAGE_TAG` 比较。
2. 下载目标版本的 `docker-compose.deploy.yml`，执行 `docker compose config --quiet`，检查部署文件、磁盘空间和当前版本。
3. 拉取目标 backend/web 镜像并要求存在仓库 `sha256` 摘要。任何失败都在停服前中止。
4. 停止 web/backend，等待 Backend 的 SIGTERM drain 完成；随后固化并停止 Redis，保证文件恢复点一致。
5. 创建 `backup-YYYYMMDD-HHMMSS.zip.partial`，其中包含 PostgreSQL custom-format dump、后端数据目录 tar、Redis 数据目录 tar、1Panel 部署密钥卷、部署 `.env`、当前 Compose 和元数据；写入完成后 `fsync`、原子改名，并复核 ZIP 结构和 SHA-256。
6. 用目标 backend 镜像独立执行 `migrate-schema up`。整批迁移在事务和 PostgreSQL advisory lock 内完成，迁移名称与 checksum 必须匹配。
7. 原子更新 `CANVAS_IMAGE_TAG` 和 Compose 文件，启动目标版本。
8. 连续检查 `/api/health/ready` 的数据库、运行时、schema 和 build version，并经过稳定窗口后才标记成功。

更新状态写入 `/var/lib/open-ai-canvas-updater/state.json`。Backend 或浏览器在切换期间断线不会终止宿主机操作，恢复后可继续读取日志。

## 自动回退

停服后的迁移、启动或健康验证失败会触发自动回退：

1. 停止目标 web/backend；
2. 再次校验恢复包 ZIP、SHA-256、PostgreSQL dump 和各数据归档；
3. 恢复包中的 `.env` 和 Compose，并校验恢复后的 Compose；
4. 恢复 1Panel 部署密钥卷，使用 `pg_restore` 重建 PostgreSQL，并恢复后端 `/data` 与 Redis 数据；
5. 恢复旧 `CANVAS_IMAGE_TAG`，启动旧服务并重新进行稳定窗口验证。

回退任一步失败时状态变为 `manual_intervention`，不伪造成功。管理后台仅在存在旧版本和已校验备份时开放人工回退按钮。

## 安装与升级约束

GHCR 镜像部署必须把 `CANVAS_IMAGE_TAG` 固定到具体 Release，不可使用 `latest`。安装更新器：

```bash
cd /opt/open-ai-canvas
curl -fsSL https://raw.githubusercontent.com/ddcat-ai/open-ai-canvas/main/scripts/install-host-updater.sh | sudo bash
sudo docker compose --env-file .env -f docker-compose.deploy.yml up -d --force-recreate backend web --wait
```

脚本会下载与当前 Release 匹配的 Linux amd64/arm64 二进制和 `SHA256SUMS`，生成随机 `CANVAS_UPDATER_TOKEN`，创建 systemd 服务、Socket 目录、状态目录和 `backups/`。Token 只保存在服务器 `.env` 与 root-only 更新器环境文件中。

## 运维检查

```bash
sudo systemctl status open-ai-canvas-updater
sudo journalctl -u open-ai-canvas-updater -n 200 --no-pager
sudo ls -lh /opt/open-ai-canvas/backups
sudo sha256sum /opt/open-ai-canvas/backups/*.zip
```

备份文件包含业务数据、密钥和部署配置，应限制为 root 访问并纳入异机备份策略。数据卷本身不是备份。更新前会先停止 Web 与 Backend，保证数据库与文件数据处于一致恢复点；如果备份阶段失败，更新器会先恢复并验证更新前服务。

## 本地 SQLite 迁移

本地 Docker 编排不使用 PostgreSQL Host Updater，而是由独立运行的本地迁移助手调用固定的 scripts/migrate-local.ps1（Windows）或 scripts/migrate-local.sh（Linux/macOS）。管理后台会在“数据与服务迁移”区块中单独显示本地迁移能力；在线版本更新仍保持不可用。

本地迁移包包含 SQLite 数据目录、上传文件、.env、Compose/Docker 配置和当前已构建的前后端镜像。导入前会校验 ZIP 清单和 SHA-256，备份目标数据与配置；迁移失败会尝试恢复原状态。迁移助手只接受带 Token 的固定导出、导入和下载请求，不提供任意 PowerShell 或 Docker 执行接口。

```text
管理员浏览器 → Backend 管理 API → Token HTTP → host.docker.internal:9714
                                              → 固定本地迁移脚本 → Docker Compose
```

Windows 启动本地服务时，scripts/start-local.ps1 会构建并启动迁移助手；Linux/macOS 请运行 scripts/start-local-migration-helper.sh。两者都会将只读 Token 文件挂载到 Backend。若 Docker 或助手未运行，业务服务仍可启动，后台仅显示本地迁移不可用；请先检查 .local/migration-helper/helper.stderr.log 和端口 9714。
