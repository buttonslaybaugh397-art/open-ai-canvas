# 后端数据库

后端通过 GORM 管理 SQLite 与 PostgreSQL 表结构。服务启动时由 `backend/internal/database/schema.go` 执行迁移；业务写路径必须通过 service 和 repository 的状态约束，不能直接依赖前端状态。

## 模型渠道与目录

| 表 | 用途 | 关键边界 |
| --- | --- | --- |
| `model_channels` | 保存系统渠道与用户渠道的连接配置 | 系统渠道密钥不进入公开目录；普通用户只能读取脱敏后的可用模型集合 |
| `channel_models` | 保存系统渠道中的产品模型标识、上游模型 ID、显示名称、模型 Logo、能力、协议和版本状态 | `icon` 只用于模型选择器展示；能力、协议、启用状态和价格仍由 service 强校验 |
| `channel_model_price_tiers` | 保存系统模型按规格匹配的上游 SKU 与价格 | 价格档与渠道模型同事务保存；未启用或未完成定价的规格不进入普通用户目录 |
| `logical_models` | 保存前台模型的公开名称、Logo、能力类型和归档状态 | 前台模型与系统渠道模型分别维护展示信息；供应线路通过 revision 和 route 关联 |

## 插件管理

| 表 | 用途 | 关键边界 |
| --- | --- | --- |
| `plugin_platform_states` | 保存管理员设置的平台可用状态 | `plugin_id` 为主键；平台停用是所有用户的硬上限，管理员变更写入审计日志 |
| `user_plugin_states` | 保存用户对官方应用插件的个人启用状态 | `(user_id, plugin_id)` 唯一；系统协议和管理员上传插件不得写入用户级状态 |

有效状态由服务端计算为 `platform_available AND user_enabled`。官方应用插件没有平台状态记录时默认可用；用户没有个人记录时默认停用，历史上全局启用的工作流插件在用户首次保存个人选择前沿用旧状态。管理员上传包的来源和作用域由宿主覆盖，不能通过 Manifest 提权。

## ComfyUI Bridge

| 表 | 用途 | 关键边界 |
| --- | --- | --- |
| `comfy_bridges` | 保存用户注册的 Bridge 身份、Token 摘要、启用状态和心跳能力 | Token 明文只在注册时返回一次；查询和日志只使用摘要 |
| `comfy_bridge_requests` | 保存云端任务交给本地 Bridge 的请求、领取状态和完成结果 | `id` 同时作为任务的 `provider_request_id`；状态按 `queued -> claimed -> succeeded/failed/cancelled` 单向流转 |

`comfy_bridge_requests` 是 Bridge 交接的真相源。后端进程重启后，未领取请求继续从数据库投递；已领取请求的迟到结果先落库，任务 worker 恢复后使用原请求 ID 读取结果，不会创建第二次本地工作流执行。请求有效期当前为两小时，过期的排队或执行记录会转为失败。

请求表保存工作流执行 payload 和结果，但不保存 Bridge Token。任务取消时，未领取请求可以确定取消；已经领取的本机工作流无法可靠中止，迟到结果会被丢弃并进入费用核对流程。

## 资源与对象存储灾备

`resources` 保存媒体的逻辑记录和主存储位置。使用云对象存储创建的新资源同时保留一份服务器本地副本，`local_backup_key` 指向 `CANVAS_BACKEND_DATA_DIR/resources` 下的相对路径；本地存储资源该字段为空。

| 字段 | 用途 | 说明 |
| --- | --- | --- |
| `provider`、`endpoint`、`bucket`、`object_key` | 主对象存储位置 | 固定记录资源创建时的供应商和对象路径，避免切换平台后历史资源串库 |
| `local_backup_key` | 本地灾备副本路径 | 只保存相对路径，服务端读取和删除时进行目录边界校验；部署必须持久化 `/data` 或 `CANVAS_BACKEND_DATA_DIR` |
| `cloud_sync_status` | 云端同步状态 | `synced`、`pending`、`recovering`；云端暂不可用时资源仍保持 `ready`，优先从本地副本提供 |
| `cloud_sync_attempts`、`cloud_sync_error` | 恢复观测信息 | 记录恢复尝试次数和最近一次安全错误摘要 |
| `cloud_sync_next_attempt_at` | 下次恢复时间 | worker 按退避时间领取待恢复资源 |
| `cloud_sync_lease_owner`、`cloud_sync_lease_expires_at` | worker 租约 | 防止多实例重复补传；过期租约可被其他实例接管 |

资源删除通过 `resource_deletion_jobs` outbox 同时清理主对象和本地灾备副本。历史云资源若没有 `local_backup_key`，仍只能在云端读取，无法追溯补齐已有本地保护。
