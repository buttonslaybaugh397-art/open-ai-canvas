## 三、本地保留和新增了什么

### 1. 管理后台统计更细，重点是统计到每个人

上游并不是没有统计：rc3 和本次检查的 v1.2.9 都有基础活跃、任务、请求、模型统计，模型行中已有媒体数、视频秒数、Token 和估算费用。我们的差异是增加统计维度、结算口径、个人明细和展示能力。

本地增强包括：

- 区分生成任务、逻辑上游请求和已结算账单，不将轮询次数当作生成次数。
- 文本、图片、视频、音频分开统计，包含任务状态、成功率、平均与 P95 耗时。
- 成功图片数、视频数、音频数、视频秒数、输入/输出/缓存 Token、已结算积分和可用的估算费用。
- 每个用户都有总览，以及按模型、按渠道、按自然日的明细；包含个人积分、视频秒数、任务与请求质量、活跃天数及登录次数。
- 增加渠道统计接口 `/api/admin/analytics/channels` 和对应视图，提供个人统计 CSV 导出。
- 后台展示 7/30/90 天区间、上一等长周期对比、每日积分消耗趋势、个人排行和详情。
- `poll`、`download` 不重复计为生成请求；成功媒体按任务计数，历史视频时长通过任务快照或关联日志回补，避免多次轮询累加。
- 积分按账单结算时间汇总，而不是一律按任务创建时间归属日期。

当前“视频平均单价”的实际实现是 **视频已结算积分 / 视频秒数，单位为积分/秒**，不是人民币/秒，也不是实付上游成本/秒。无有效秒数时显示 `--`。

代码依据：`backend/internal/service/analytics.go` 的 `AnalyticsUserRow`、`AnalyticsUserModelRow`、`AnalyticsUserChannelRow`、`AnalyticsUserDayRow`、`generatedVideoSecondsByTask`；`backend/internal/repository/analytics.go`；`web/src/pages/admin/components/analytics-panel.tsx` 的 `averageVideoCreditsPerSecond`。

最新上游核对：`backend/internal/app/analytics.go` 仍是较基础的统计结构；其 `web/src/pages/admin/components/analytics-panel.tsx` 与 rc3 的 blob 相同，未包含上述本地面板增强。

### 2. 用户积分中心增加个人消耗汇总

本地积分中心新增今日、昨日、本周、本月消耗和本月每日趋势。

口径是登录用户自己的 `consume` 积分流水，按 `Asia/Shanghai` 统计，周一为一周开始；独立查询聚合，不受当前流水列表分页和筛选影响。充值、冻结、退款不直接算作消耗，因此这也不是包含退款冲销的净支出报表。

代码依据：`backend/internal/service/finance.go` 的 `WalletConsumptionSummary`、`walletConsumption`；`backend/internal/repository/finance.go` 的 `CreditConsumptionDaily`；`web/src/pages/wallet/index.tsx`。

最新上游的 `backend/internal/app/finance.go` 中，`WalletSummary` 仍是账户、流水、分页和积分策略，没有本地增加的 `consumption` 汇总。

### 3. 用户名修改和管理员密码重置流程

本地用户编辑支持修改登录用户名：校验格式，忽略大小写查重，按同一个用户 ID 更新，不新建账号。积分、任务和素材归属不因改名而变化。改名和审计在事务中处理，并防止过时用户名写入覆盖新值；普通登录及 OAuth 登录仅更新相关登录字段，避免将旧用户名写回。

密码重置的差异需要分清：**上游已有后端修改密码字段及旧会话清理，本地不是从零新增后端重置能力。** 本地主要补齐：

- 用户列表的独立“重置密码”入口，手动输入并确认，或生成 24 位安全随机密码。
- 单独提交密码，不把列表中可能过时的其他用户字段一并写回。
- 保存成功后显式复制，新密码只保留在弹窗内存，不读取旧密码。
- 用户更新、会话撤销和脱敏审计一并进入事务；审计只记录变更标记，不记录密码或哈希。
- 重置当前管理员自己的密码时清除本人 Cookie，并走重新登录流程。
- 补充前后端验证与回归测试。

代码依据：`backend/internal/service/admin.go` 的 `UpdateUserRequest`、`UpdateUser`；新增 `backend/internal/repository/admin_user.go`；`backend/internal/handler/auth.go`；`web/src/pages/admin/users/users-password-modal.tsx` 和 `users-password.ts`。

最新上游 `backend/internal/app/admin.go` 的更新请求没有 `username` 字段；用户列表和编辑抽屉与 rc3 相同。上述本地改名及独立重置流程不能被直接覆盖掉。

### 4. 平台存储配置恢复和管理员显式读取凭据

本地针对备份恢复后加密密钥不匹配的场景做了处理：管理员仍可读取非敏感配置和 `credentialsRequireReset` 状态，重新输入并保存凭据；实际资源访问仍拒绝使用无法解密的凭据。

另增加 `/api/admin/settings/oss/credentials`：管理员主动读取存储凭据，校验权限、限频并审计，响应禁止缓存；普通配置读取仍保留脱敏边界。该能力只针对平台存储配置，不代表所有平台密钥都可明文读取。

缺少原始 `.settings-key` 时不能还原旧密文中的秘密，恢复能力是允许重新配置，不是绕过加密。

代码依据：`backend/internal/service/settings.go` 的 `AdminOSSCredentials`、`readOSSSettingForAdmin`；`backend/internal/service/storage_location.go`；`backend/internal/handler/auth.go`；`web/src/pages/admin/settings/storage-settings-page.tsx`。

最新上游 `backend/internal/app/settings.go` 仍直接读取并解密平台配置，解密失败会中断，没有上述本地恢复状态和显式读取接口。本次未读取任何真实凭据。

### 5. 任务订阅快照防回退

本地在共享任务订阅入口增加状态推进判断：终态不被迟到的排队或运行快照覆盖，成功结果优先于失败/取消结果，并检查时间戳与进度；观察中断且仍有监听者时自动重连，无监听者时清理重试定时器。

实际重连默认等待 **2 秒**，不是指数退避。此前合并记录里“自动退避重连”的表述不够精确，以当前代码为准。

代码依据：`web/src/services/api/task-center.ts` 的 `generationTaskSnapshotCanAdvance`、`createGenerationTaskSubscriptionService` 和相邻测试。

最新上游的同名文件与 rc3 完全相同，仍未包含这一小范围保护。不过这仅是共享订阅快照的保护，不能据此声称所有刷新、持久化、后台生成状态问题都已解决。上游 v1.2.9 的画布保存冲突修复属于另一条链路，应另外接入。

### 6. 画布提示词高度和松手连线吸附

本地把提示词编辑器上限从 8 行扩大到 16 行，统一拖拽与键盘限位，并在参考架高度变化时保留文本编辑区高度。

拖动连线经过卡片正文时，线头继续跟随指针并高亮目标；松手落在合法目标卡片正文后才建立连接。端口附近的吸附仍保留，批量连线、分镜行端口与非法连线规则继续遵循现有约束。

代码依据：`web/src/components/canvas/canvas-node-prompt-panel.tsx`、`web/src/lib/canvas/canvas-prompt-height.ts`、`canvas-connection-snap.ts`、`web/src/pages/canvas/use-canvas-connection-controller.ts` 及渲染层测试。

上游新加的“拖到提示词参考图上替换引用”会修改同一连接控制器和提示词面板。两者不是互相替代的需求，下次合并需要明确参考图替换、卡片正文连接、端口连接的命中优先级。

### 7. 少数渠道和牌谱插件

本地保留了 GlobalAiOpc 图片/视频、AIStarsLab 图片/视频、汇取云视频、微进视频的接口注册及对应适配，涉及独立结果端点、媒体准备、路由/质量/参考参数和轮询行为。汇取云 933 模型保留 multipart 媒体处理，避免错误地一律转换为 URL。

本地插件加载器还支持受信任宿主解析器下的 `host:providers` 多 Provider 绑定；这不是允许任意插件执行任意宿主代码。

牌谱 `paipu-net` 为本地新增插件，包含源码 manifest、说明和 `.yingce-plugin` 安装包；另外，本地 AutoDL 插件安装包与 rc3 不同。

代码依据：`backend/internal/protocol/channel_plugins.go`、`builtin.go`、`manifest.go`；`backend/internal/service/provider_protocol.go`、`provider_aistarslab.go`、`provider_huiquyun.go`、`provider_weijin.go`；`plugin-packages/paipu-net/`。

本次没有重新对牌谱官网逐项校对，也没有发送真实计费请求，因此只确认插件实现差异，不保证供应商今天的所有参数都已实测。v1.2.9 又更新了声明式协议和插件包，不能用本地旧包覆盖上游整套插件目录。

### 8. 旧数据库升级桥接与 Windows 支持

数据库方面，本地为旧稳定分支的历史迁移记录增加精确 checksum 谱系识别，解决旧数据库与上游迁移版本号重叠的问题。只接受已知、连续的旧谱系后再升级，不是忽略 checksum 或跳过校验。最新上游 `migrations.go` 与 rc3 相同，因此仍需保留本地桥接。

Windows 方面，本地增加系统磁盘指标实现和排除重复编译的 build tag；另有少量相邻测试清理和资源 payload 断言修正。

代码依据：`backend/internal/database/migrations.go`、`migrations_lineage_test.go`；`backend/internal/service/system_metrics_windows.go`、`system_metrics_other.go`。

已有数据库挂载、备份恢复和 9 月 5 日数据补齐属于运行数据操作，不是 Git 上游源码差异。本文不重新核验账目，也不修改这些数据。

## 五、单独保留清单：为什么不能直接覆盖

这里列的是不应被无条件覆盖的本地行为，不是拒绝合并整个上游模块。

| 本地保留项 | 不直接覆盖的原因 | 下次合并处理 |
| --- | --- | --- |
| 详细统计及个人明细 | 上游没有相同的统计维度与结算口径，覆盖会丢失个人用量、积分和秒均积分视图 | 迁入上游新结构，保留 API、类型、页面及专项测试 |
| 个人每日/昨日/周/月消耗 | 最新上游钱包汇总仍缺少该能力 | 保留消费聚合，并明确时区和流水口径 |
| 用户名修改 | 最新上游更新接口不支持用户名字段 | 保留校验、事务审计、并发与归属保护 |

## 七、当前仍需说清的边界

1. **统计时区不一致。** 管理统计的纯日期查询及日桶按 UTC，个人积分中心按北京时间。相同中文日期标签可能覆盖不同的 24 小时，跨日账目不能直接逐行对比。后续应统一口径或显式标注。本次只记录，未修改。
2. **平均单价不是货币成本。** 当前视频秒均价为积分/秒；上游费用是可用时的估算字段，不自动等于实际账单。需要人民币成本和利润报表时必须另行定义换算、币种和退款口径。
3. **任务日期与结算日期不同。** 当前同一区间的视频秒数与已结算积分不保证来自完全相同的一组任务，跨日完成或结算时尤其如此。若要财务级逐单秒均成本，需要按任务和账单对齐后再计算，不能只看两个区间汇总值相除。
4. **8 个账号管理新文件尚未跟踪。** 只备份 `git diff` 或只提交当前暂存区可能漏掉这些实现与测试。后续收尾必须逐项检查，但本次不自动暂存或提交。
5. **无冲突不等于完成。** 当前仍有 `MERGE_HEAD`，没有合并提交，更没有已发布的新镜像；不能把正在运行的本地源码与某个远端镜像标签视为完全一致。
6. **验证范围有限。** 本次做 Git/源码/公开上游资料核对，没有重跑构建、测试或真实生成。历史记录里统计、快照、迁移谱系和账号管理有专项验证，但完整 Vite 生产构建曾因 Windows 内存不足未完成，不能由专项通过推导整个生产发布已验证。
