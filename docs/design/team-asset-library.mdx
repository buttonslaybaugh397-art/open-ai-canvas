# 团队素材库产品与实施方案

本文定义影策团队素材库的产品边界、权限模型、数据结构、接口、页面、迁移和验收标准。目标不是开放一个全站公共素材池，而是交付具备明确团队边界、成员权限和资源生命周期的可用协作功能。

## 1. 现状审计

仓库已经存在一套未完成的团队素材骨架：

- 后端已有 `TeamAsset`、`TeamAssetFolder`、`TeamAssetResource` 模型，以及素材和文件夹的 service、repository、handler。
- 前端已有 `team-assets.ts` API 客户端和 `TeamAssetBrowser` 浏览组件。
- 当前代码支持文本、图片、视频、音频和 3D 模型，具备搜索、类型筛选、文件夹、预览、下载、重命名、移动和取消共享的基础界面。
- 当前测试只覆盖了部分文件夹生命周期和“上传者或平台管理员可编辑”的权限。

但这套骨架当前不能作为正式功能启用：

1. `RegisterTeamAssetRoutes` 没有注册到主服务，所有 `/api/team-assets` 请求实际不可达。
2. 团队素材组件没有接入 `/assets` 页面、画布素材选择器或创作页。
3. 数据没有 `team_id`；任意登录用户理论上都会读取同一个全站公共池，不具备租户隔离。
4. 列表一次读取全部素材和全部用户，再在浏览器分页，数据量增长后不可用。
5. 文件夹也没有团队归属，素材可以被移动到任意用户创建的文件夹。
6. 当前 PUT 接收浏览器提交的完整素材 JSON，服务端难以表达分享、复制、版本冲突和审计语义。
7. 平台管理员被直接视为所有团队素材的编辑者，不符合团队隐私和最小权限原则。
8. 缺少成员管理、邀请、团队切换、配额、批量操作、操作审计和跨成员集成测试。

结论：保留现有媒体校验、资源关联和部分 UI 组件作为实现基础，但不能只注册旧路由就上线。

## 2. 产品目标

首个正式版本需要让用户完成以下闭环：

1. 创建或加入团队，并在多个团队之间切换。
2. 从个人素材库批量共享文本、图片、视频、音频和 3D 模型到指定团队目录。
3. 团队成员按权限浏览、搜索、预览、下载、整理和取消共享素材。
4. 在画布、创作页和项目素材选择器中选择团队素材。
5. 将团队素材复制到个人素材后再用于作品，保证退出团队后已使用内容不失效。
6. 上传者和团队管理员能够追踪素材来源、更新时间和关键操作。
7. 所有读取、文件下载和写入均由后端按当前成员关系校验。

### 非目标

首版不实现素材评论、在线同时编辑、版权交易、外部公开分享链接、跨部署团队、复杂审批流和对象级自定义 ACL。这些能力不能阻塞安全、稳定的团队素材闭环。

## 3. 核心概念

| 概念 | 含义 |
| --- | --- |
| 团队 | 素材共享和成员权限的租户边界；一个用户可以属于多个团队 |
| 团队成员 | 用户与团队的关系，包含角色和状态 |
| 团队素材 | 从个人素材共享或直接上传形成的团队快照，不与个人素材的后续编辑自动互相覆盖 |
| 团队文件夹 | 只属于一个团队的目录结构，首版最多三层 |
| 复制到我的素材 | 将团队素材物化为当前用户的个人素材和可持续访问的资源 |
| 取消共享 | 移除团队素材，不删除上传者的个人素材，也不影响其他成员已经复制的个人副本 |

团队素材采用“快照”而不是双向同步。个人素材共享后，个人侧重命名或替换文件不会静默修改团队版本；上传者可显式执行“更新共享版本”。这样可以避免团队作品在不知情时发生变化。

## 4. 权限模型

团队角色固定为四级：

| 操作 | 查看者 | 编辑者 | 管理员 | 所有者 |
| --- | --- | --- | --- | --- |
| 浏览、搜索、预览、下载 | 是 | 是 | 是 | 是 |
| 复制到个人素材、用于画布 | 是 | 是 | 是 | 是 |
| 共享或直接上传素材 | 否 | 是 | 是 | 是 |
| 编辑、移动、取消共享自己的素材 | 否 | 是 | 是 | 是 |
| 编辑、移动、取消共享他人素材 | 否 | 否 | 是 | 是 |
| 新建文件夹 | 否 | 是 | 是 | 是 |
| 重命名、删除任意文件夹 | 否 | 否 | 是 | 是 |
| 邀请成员、调整查看者/编辑者 | 否 | 否 | 是 | 是 |
| 任命管理员、移除管理员 | 否 | 否 | 否 | 是 |
| 修改团队、转让或删除团队 | 否 | 否 | 否 | 是 |

平台管理员不自动获得团队内容读取权。确需支持排障时，应使用单独、限时、可审计的支持访问机制，而不是在普通 service 中绕过成员校验。

所有 service 方法必须先得到 `TeamMembership`，repository 查询必须同时带 `team_id` 和对象 ID。只在前端隐藏按钮不构成权限控制。

## 5. 数据模型

### `teams`

| 字段 | 说明 |
| --- | --- |
| `id` | 团队 ID |
| `name` / `name_key` | 展示名和规范化名称 |
| `owner_user_id` | 唯一所有者 |
| `avatar_resource_id` | 可选团队图标 |
| `status` | `active`、`archived` |
| `created_at` / `updated_at` | 时间 |

### `team_members`

使用 `(team_id, user_id)` 唯一索引，包含 `role`、`status`、`invited_by`、`joined_at`。有效状态为 `active`；移除成员时保留审计记录或写入独立审计表。

### `team_invitations`

保存团队、目标邮箱或用户、目标角色、一次性 Token 哈希、邀请人、过期时间和消费时间。邀请明文 Token 不进入数据库和日志。已存在账号可以站内接受；邮件发送能力不可用时允许管理员复制一次性邀请链接。

### `team_assets`

在现有字段上增加并规范化：

- `team_id`：非空，所有列表和唯一索引的第一维。
- `owner_user_id`：分享者或上传者。
- `source_asset_id`：可选个人素材来源，仅用于追踪和显式更新。
- `folder_id`：可选，必须属于同一团队。
- `kind`、`category`、`status`、`title`、`description`。
- `tags_json`、`payload_json`：标签和按类型校验后的内容快照。
- `content_hash`：用于批量分享时识别重复内容。
- `revision`：从 1 递增，用于并发更新和 `409 Conflict`。
- `created_at`、`updated_at`。

索引至少包括：

- `(team_id, updated_at DESC, id)`：稳定分页。
- `(team_id, folder_id, updated_at DESC)`：目录分页。
- `(team_id, kind, updated_at DESC)`、`(team_id, category, updated_at DESC)`。
- `(team_id, owner_user_id, updated_at DESC)`。
- `(team_id, content_hash)`：重复提示，不强制全局唯一。

### `team_asset_folders`

增加 `team_id`、`parent_id`、`name_key`、`position` 和 `created_by`。`(team_id, parent_id, name_key)` 唯一；删除文件夹时素材移动到父目录，不能级联删除素材。

### `team_asset_resources`

继续作为团队素材与资源的显式引用表，增加必要的 `(team_asset_id, resource_id)` 主键和资源反查索引。团队资源读取授权必须同时满足：

1. 当前用户是团队有效成员。
2. 目标资源被该团队中尚存在的素材引用。
3. 素材状态允许读取。

### `team_asset_audit_logs`

记录团队、操作者、动作、素材或文件夹 ID、前后版本摘要、时间和 request ID。首版记录 `share`、`update`、`move`、`unshare`、`download`、`member_role_change`，不记录素材正文、下载 URL 或密钥。

## 6. 资源与删除策略

### 个人分享到团队

前端只提交个人 `asset_ids`、目标团队和文件夹。后端读取当前用户个人素材，校验资源归属、上传完成状态和配额，再创建团队快照及 `team_asset_resources`。不再接受客户端构造任意完整素材对象作为创建协议。

浏览器临时 `blob:`、`data:` 或本地 IndexedDB 文件必须先上传后端资源存储。批量分享先做预检，再逐项返回成功、重复、超额和失败原因。

### 团队素材用于作品

选择团队素材时调用“复制到我的素材”接口，由后端物化个人素材。媒体资源首版执行服务端对象复制并创建新的个人 Resource 记录；文本只复制结构化内容。完成后画布和项目只引用个人副本。

这个策略刻意用少量存储换取清晰的权限与生命周期：成员离开团队、团队素材取消共享或团队归档后，已经用于个人作品的素材不会变成 403/404。后续可以在 Resource 层引入不可变 Blob 和引用计数实现物理去重，但不能在首版用共享对象键冒充权限隔离。

当前实现允许所有活跃成员（含 `viewer`）复制，每次接受 1 到 50 个 `assetIds`。服务端先按 `team_id` 完成全部素材和资源授权检查，再检查个人素材数量、结构化数据、每日上传量和文件总容量；同一批次重复素材 ID 会被忽略，多个素材引用同一资源时只创建一个资源副本。最终个人素材批量事务失败时，本次创建的资源记录和物理对象会被回收。

### 删除

- 取消共享只删除团队快照及团队资源引用。
- 上传者的个人原件和成员已经复制的个人副本不受影响。
- 删除个人素材时，如其资源仍被团队素材引用，现有资源引用检查必须阻止物理删除或只删除个人结构化记录。
- 删除团队前必须二次确认；团队进入 `archived`，后台异步清理无引用资源，不在 HTTP 请求内执行大批量物理删除。

## 7. API 合同

新接口统一放在 `/api/teams/:teamId` 下，不继续扩展无租户边界的 `/api/team-assets`：

### 团队和成员

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/teams` | 当前用户的团队列表和角色 |
| `POST` | `/api/teams` | 创建团队并成为所有者 |
| `GET` | `/api/teams/:teamId` | 团队详情和当前权限 |
| `PATCH` | `/api/teams/:teamId` | 修改团队信息 |
| `GET` | `/api/teams/:teamId/members` | 成员分页 |
| `POST` | `/api/teams/:teamId/members` | 按用户名添加已有活跃账号 |
| `PATCH` | `/api/teams/:teamId/members/:userId` | 调整角色 |
| `DELETE` | `/api/teams/:teamId/members/:userId` | 移除或退出团队 |

### 素材和文件夹

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/teams/:teamId/assets` | 服务端分页、筛选和搜索 |
| `GET` | `/api/teams/:teamId/assets/:assetId` | 素材详情 |
| `POST` | `/api/teams/:teamId/assets/share` | 从个人素材批量共享 |
| `POST` | `/api/teams/:teamId/assets/upload` | 直接上传并创建团队素材 |
| `PATCH` | `/api/teams/:teamId/assets/:assetId` | 修改标题、标签、目录，携带 `revision` |
| `POST` | `/api/teams/:teamId/assets/:assetId/update-from-source` | 显式更新共享快照 |
| `POST` | `/api/teams/:teamId/assets/import` | 批量复制到当前用户个人素材 |
| `POST` | `/api/teams/:teamId/assets/batch-move` | 批量移动 |
| `DELETE` | `/api/teams/:teamId/assets/:assetId` | 取消共享 |
| `GET` | `/api/teams/:teamId/folders` | 目录树和计数 |
| `POST` | `/api/teams/:teamId/folders` | 新建目录 |
| `PATCH` | `/api/teams/:teamId/folders/:folderId` | 重命名或移动目录 |
| `DELETE` | `/api/teams/:teamId/folders/:folderId` | 删除目录，内容上移 |

列表参数使用 `page`、`page_size`、`q`、`kind`、`category`、`folder_id`、`owner_id`、`sort`。响应返回 `items`、`page`、`pageSize`、`total` 和分类/目录计数。`page_size` 最大 100，搜索和排序在数据库完成。

写接口使用幂等键；版本不一致返回 HTTP 409 和最新摘要。权限不足返回 403，团队或素材不存在返回 404，不能用 404 掩盖已确认的普通输入错误。

已实现的复制请求为 `{ "assetIds": ["team-asset-id"] }`，成功响应为 `{ "imported": [{ "teamAssetId": "...", "asset": { ... } }] }`。返回的 `asset` 已使用新的个人素材 ID，并将所有已识别的团队资源引用改写为当前用户持有的资源 ID；前端应增量合并这些素材，不能用一次服务端响应覆盖浏览器中尚未同步的个人素材。

## 8. 前端信息架构

### 素材页 `/assets`

页面顶部增加一级范围切换：

- `我的素材`：保留现有个人素材功能。
- `团队素材`：展示当前团队素材；有多个团队时显示团队选择器。

团队素材页提供：

- 关键词、类型、分类、上传者和更新时间筛选。
- 左侧或横向文件夹导航，展示根目录和目录计数。
- 网格/列表视图、服务端分页、空态和错误重试。
- 卡片展示素材类型、标题、分享者、更新时间和共享版本。
- 多选后的“复制到我的素材”“移动”“取消共享”批量栏，动作按权限自动收敛。
- 显式更多按钮和右键菜单保持同一命令来源。
- 团队选择器旁提供成员管理入口；所有成员可查看名单，所有者/管理员按权限添加、调整或移除成员，非所有者可主动退出。

个人素材卡片新增“共享到团队”。批量选择时也可一次共享，并在弹窗选择团队、文件夹、标签和重复处理方式。

### 统一素材选择器

素材选择器来源调整为 `我的素材 / 团队素材 / 插件来源`。团队来源支持团队、目录和类型筛选。确认选择时先调用批量 import，得到个人素材 ID 后再走现有画布节点或创作引用流程。

画布、创作页、时间线和项目资产选择器必须复用同一团队素材适配器，不能各自拼装团队 API。时间线继续按现有类型规则限制只能选择音视频。

当前实现已完成统一适配：选择器按团队、文件夹、类型、关键词和服务端分页读取素材；团队项使用带团队作用域的临时选择 ID，确认后按团队批量调用 import，并把返回的个人副本 ID 与素材对象交给原调用方。导入结果增量合并到个人素材 store，不覆盖未同步的本地素材。

画布与项目画布支持文本、图片、视频和音频；创作页按图片/视频模式限制类型；角色三视图、角色声音和项目主图分别只请求图片、音频和图片；时间线只提供视频与音频分类。任何团队导入出现部分缺失时都中止后续引用，避免把失效的团队临时 ID 写入作品。

### 团队管理

设置或独立 `/teams/:teamId/settings` 页面提供团队资料、成员、邀请和危险操作。成员列表显示角色、加入时间和状态；所有者转让和团队归档必须二次确认。

## 9. 状态与同步

- React Query key 必须包含 `userId` 和 `teamId`，切换账号或团队时清理旧缓存。
- 团队素材不写入当前个人素材 Zustand/localforage store；只有 import 成功后的个人副本进入个人同步链路。
- 创建、编辑、移动和取消共享成功后精确更新或失效对应团队 query。
- 首版不做 WebSocket 协同；窗口重新聚焦、成员操作成功和 30 秒低频刷新足够。编辑冲突由 `revision` 阻止静默覆盖。
- 加载态、本地缓存态和服务端保存成功必须明确区分，不能把查询缓存写入当成团队已保存。

## 10. 安全与配额

- 所有对象读取、文件下载和写入在 service 校验成员身份及角色。
- 团队 ID 不从 Cookie 或全局变量猜测，始终来自路径并参与 repository 条件。
- 资源文件接口增加团队授权分支，但只接受数据库中的 `team_asset_resources`，不接受前端声明。
- 上传继续使用现有 MIME、大小、格式和存储策略；文件名不能决定 MIME。
- 团队设置独立素材数量和存储字节配额；批量分享、直接上传和复制到个人均先预检再执行。
- 邀请 Token、资源 URL、Cookie、第三方密钥和素材正文不写入审计日志。
- 搜索结果、目录计数和下载接口都不能泄露非成员团队是否存在。

## 11. 数据迁移

新增 Schema 版本，不修改已发布迁移校验和。SQLite 与 PostgreSQL 都需要覆盖迁移测试。

现有 `team_assets` 可能来自未启用功能，迁移采取保守策略：

1. 为每个现有 `owner_user_id` 创建仅该用户可见的“迁移素材库”团队。
2. 将该上传者现有团队素材和文件夹归入自己的迁移团队。
3. 不把所有活跃用户自动加入一个默认团队，避免将历史数据暴露给全站账号。
4. 管理员只能看到迁移统计，不能自动读取素材正文。
5. 迁移完成后旧 `/api/team-assets` 保持不注册；代码调用全部切换到新接口后删除旧 handler。

## 12. 实施里程碑

### M1：安全数据底座

- 新增团队、成员、邀请、审计表和 `team_id` 迁移。
- 重写 repository 为团队作用域查询，完成角色校验和分页。
- 补齐资源读取授权、配额、并发 revision 和批量事务。
- 交付团队/成员、素材、文件夹 API 和 OpenAPI/文档合同。

退出条件：两个团队的成员无法通过列表、详情、下载或猜测 ID 读取彼此数据；SQLite/PostgreSQL 集成测试通过。

### M2：可用素材页

- `/assets` 接入“我的素材/团队素材”和团队选择器。
- 完成分享、直接上传、预览、下载、搜索、分页、文件夹和批量管理。
- 接入成员角色对应的按钮和错误反馈。

退出条件：编辑者可从个人素材批量共享，查看者可检索并复制，非授权动作前后端都拒绝。

### M3：创作闭环

- 统一素材选择器接入团队来源。
- 画布、创作页、项目资产和时间线完成团队素材选择与类型过滤。
- import 后物化个人副本，并验证退出团队、取消共享和刷新后作品不丢资源。

退出条件：文本、图片、视频、音频和 3D 模型分别完成“共享 -> 另一成员选择 -> 刷新 -> 继续可用”的端到端测试。

### M4：运营与发布

- 团队中心已支持名称、描述、成员数、素材数、唯一资源存储量和配额展示；所有者可调整素材与存储配额，其他成员只读。
- 批量共享在单事务中按最终用量校验，素材或存储超限时整批回滚；存储按唯一资源计费。
- 团队关键写操作已写入只增审计记录，团队中心为 owner/admin 提供稳定分页查询；事件不保存素材正文、资源地址或凭据。
- 邀请链接闭环已完成：独立团队工作区可创建限时一次性邀请、撤销待使用邀请，加入页提供安全预览与事务化接受；数据库和审计只保存 Token 哈希或邀请 ID。
- 待完成诊断指标和后台清理任务。
- 增加诊断事件、慢查询指标、资源复制失败恢复和后台清理任务。
- 更新功能清单、数据库文档、部署迁移说明和待测试清单。

退出条件：生产迁移演练、回滚演练、权限矩阵测试、浏览器关键路径和容器构建全部通过。

预计总工作量为 12 到 18 个工程日，适合按 M1/M2、M3、M4 三个可独立验收的迭代交付；资源物理去重和评论协作不计入该估算。

## 13. 测试矩阵

### 后端

- 四种角色对每个读取和写接口的表驱动权限测试。
- A 团队成员使用 B 团队的素材、目录和资源 ID 均失败。
- 上传者被移除、团队归档、素材取消共享后的资源访问测试。
- 分享、更新、批量移动、目录删除和 import 的事务回滚测试。
- revision 冲突、幂等重试、重复分享和配额竞争测试。
- SQLite 与 PostgreSQL 迁移、索引和分页稳定性测试。

### 前端

- 团队切换不串缓存；账号切换不显示上一账号团队数据。
- 服务端分页、筛选、目录计数、空态、错误重试和移动端布局。
- 按权限隐藏和禁用动作，但人工调用 API 仍由后端拒绝。
- 批量分享和 import 的部分失败结果可逐项理解并重试。
- 团队素材在画布、创作页、项目和时间线的类型过滤正确。

### 端到端验收

使用所有者、编辑者、查看者和非成员四个真实会话，至少验证：

1. 所有者创建团队并邀请三种角色。
2. 编辑者共享五种素材并创建目录。
3. 查看者搜索、预览、下载并复制素材到个人库。
4. 查看者把个人副本加入画布并刷新页面，节点与媒体仍在。
5. 所有者取消原团队共享并移除查看者，已有画布仍可使用个人副本。
6. 非成员无法读取列表、详情、原始文件或目录计数。

## 14. 发布门槛

以下条件全部满足后才可启用团队素材入口：

- 新团队作用域接口已替换旧的全站公共池接口。
- 数据库迁移在 SQLite 和 PostgreSQL 通过，并有迁移前备份说明。
- 资源文件读取已覆盖团队成员校验，跨团队 ID 测试通过。
- 页面使用服务端分页，没有全量读取团队素材或全量用户。
- 画布使用团队素材时已物化个人副本，不依赖持续团队成员身份。
- 权限矩阵、配额、审计、批量失败和删除生命周期测试通过。
- 前后端生产构建及部署容器健康检查通过。

在这些门槛之前，不应仅通过注册现有 `RegisterTeamAssetRoutes` 或展示现有 `TeamAssetBrowser` 来“快速启用”，因为那会把所有登录用户放进同一素材池。
